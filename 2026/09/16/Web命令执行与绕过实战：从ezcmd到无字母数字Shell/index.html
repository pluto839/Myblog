Web命令执行与绕过实战：从ezcmd到无字母数字Shell

前言

命令执行（Command Injection / RCE） 是 Web 安全的高频考点，也是 CTF 里”工厂”味最浓的一类题。它的本质是：程序把用户输入拼接进了系统命令，而没有做安全处理，导致攻击者能执行任意命令。

这篇笔记来自我连刷的一整套命令执行靶场（ezcmd 系列），从最简单的不设防，到 escapeshellcmd() 转义、空格/分号过滤、黑名单正则、preg_replace /e 漏洞，一路打到无字母数字 WebShell。我把 14 道 ezcmd 和 3 道 basic 的完整思路与解题脚本整理如下。

先看各种绕过场景对应的边界条件，方便总览：

  • c 八进制 143，a 八进制 141，t 八进制 164
  • 所以 $'\143\141\164' 在 Shell 眼里就等于 cat

3.6 ezcmd_13：preg_replace /e 漏洞

这是一道非常经典的 preg_replace 函数的 /e 修饰符代码执行漏洞（PHP 5.5.0 以下版本）。

代码分析：

关键点：preg_replace('/(' . $re . ')/ei', ...)——第一个参数里有 /e 修饰符。i 忽略大小写，e 就是传说中万恶之源的 eval（执行） 修饰符。

当 PHP 发现 /e 时，它不会把第二个参数 strtolower("\\1") 当成普通文本替换，而是当成 PHP 代码去执行！

Payload 如何生效：

代入后第一个参数变成 /(.*)/ei，.* 匹配一切。正则成功匹配整个 {${system('ls')}}，于是第二个参数变成 strtolower("{${system('ls')}}")，被当成代码执行。

在 PHP 双引号字符串中，遇到 ${} / {${}} 这种复杂变量解析语法，引擎会先执行大括号里的函数，获取返回值。于是 system('ls') 就这样被无情执行了。

这里有个经典的坑：为什么 Payload 里不能加分号？

  • 正常 system('ls'); 是一句”完整句子”，分号 ; 是句号，需要它来结束
  • 但这里是”填空题”：system(...) 是被包裹在双引号字符串 {${ }} 结构里的。PHP 期待的是一个能得出结果的”短语”，而不是完整的”句子”
  • 加分号写成 {${system($_GET[cmd]);}}，就相当于在填空题格子里硬塞句号，直接抛语法错误

写在最后

这一整套 ezcmd 题目把命令执行的绕过手法从易到难串得非常完整，核心思想就一件事：

任何”看似过滤”都想办法找它的盲区——不过滤空格就抓空格，不过滤参数就偷渡参数，不会过滤二次解析就利用二次解析。

刷 Web 命令执行，先看过滤了什么，再想它没过滤什么。把上面速查表的思路都过一遍，大部分 RCE 题都能拿下。
